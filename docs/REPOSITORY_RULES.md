# Repository rules

1. The completed-project catalogue is an evidence-backed build log, not a wishlist.
2. The current baseline is one completed serial bring-up project. Do not represent a target count such as 25 as completed work.
3. Each project has exactly one canonical folder and a stable ID.
4. Keep project code in its project folder; avoid one global folder of unrelated sketches.
5. Keep board, difficulty, category, language and technology metadata consistent between `metadata.json`, `catalog/projects.json` and `catalog/PROJECT_INDEX.csv`.
6. Keep only genuine, relevant categories. A project can be cross-listed when its built functionality qualifies.
7. Record INR prices with their date and source; otherwise say the price was not recorded.
8. Never commit credentials, secrets or private network/device inventories.
9. Record limitations, untested steps and assumptions explicitly.
